# المعلم الذكي — دفتر التحضير الذكي

منصة تعليمية عربية تعمل باتجاه RTL لمساعدة المعلم على إعداد خطط الدروس، تحليل الصور والرسوم التعليمية، توليد الاختبارات بالذكاء الاصطناعي، إدارة بنك الأسئلة، حفظ الأرشيف، وتصدير الملفات الرسمية بصيغ PDF وWord. يتضمن المشروع واجهة ويب كاملة، خادماً بـ Express وtRPC، قاعدة بيانات MySQL/TiDB عبر Drizzle ORM، تخزيناً سحابياً للملفات، وغلاف Android باستخدام Capacitor.

> **حالة البيانات:** النسخة الحالية مهيأة للاستخدام الأول، وقد تم تفريغ البيانات التعليمية السابقة من قاعدة البيانات. بنية الجداول والميزات البرمجية ما زالت موجودة، ويمكن البدء بإضافة بيانات جديدة.

## المتطلبات

### لتشغيل الويب والخادم

يحتاج المشروع إلى Node.js حديث، وpnpm، وقاعدة MySQL/TiDB، وقيم متغيرات البيئة الموضحة لاحقاً. يوصى باستخدام Node.js 20 أو أحدث، بينما يحدد `package.json` مدير الحزم `pnpm@10.4.1`.

تحقق من الأدوات قبل البدء:

```bash
node --version
pnpm --version
git --version
```

### لبناء Android

بالإضافة إلى المتطلبات السابقة، تحتاج إلى JDK 21 أو إصدار متوافق مع Android Gradle Plugin، وAndroid Studio أو Android SDK يتضمن منصة Android حديثة و`platform-tools` و`build-tools`. يجب ضبط `ANDROID_HOME` أو `ANDROID_SDK_ROOT` وإضافة أدوات SDK إلى `PATH`.

## التثبيت المحلي

ثبّت الاعتماديات باستخدام ملف القفل حتى تحصل على نفس الإصدارات التي تم اختبارها:

```bash
pnpm install --frozen-lockfile
```

إذا فشل الأمر بسبب اختلاف إصدار pnpm، استخدم مدير الحزم المحدد في `package.json` أو فعّل Corepack ثم أعد التثبيت:

```bash
corepack enable
corepack prepare pnpm@10.4.1 --activate
pnpm install --frozen-lockfile
```

## إعداد متغيرات البيئة

أنشئ ملفاً باسم `.env` في جذر المشروع أثناء التطوير المحلي. لا ترفع هذا الملف إلى GitHub؛ فهو مستبعد في `.gitignore`.

### متغيرات الخادم والمصادقة

| المتغير                 | الاستخدام                                           |              الحالة |
| ----------------------- | --------------------------------------------------- | ------------------: |
| `DATABASE_URL`          | رابط اتصال MySQL/TiDB.                              |               ضروري |
| `JWT_SECRET`            | توقيع جلسات المستخدم. يجب أن يكون عشوائياً وطويلاً. |               ضروري |
| `VITE_APP_ID`           | معرّف تطبيق Manus OAuth.                            |      ضروري للمصادقة |
| `OAUTH_SERVER_URL`      | عنوان خادم OAuth الخلفي.                            |      ضروري للمصادقة |
| `VITE_OAUTH_PORTAL_URL` | رابط بوابة تسجيل الدخول.                            |      ضروري للمصادقة |
| `OWNER_OPEN_ID`         | معرّف مالك المشروع في إعداد Manus.                  | ضروري في بيئة Manus |
| `OWNER_NAME`            | اسم مالك المشروع.                                   | ضروري في بيئة Manus |

### متغيرات الذكاء الاصطناعي والتخزين

| المتغير                       | الاستخدام                                             |    الحالة |
| ----------------------------- | ----------------------------------------------------- | --------: |
| `BUILT_IN_FORGE_API_URL`      | عنوان خدمات Manus المدمجة للذكاء الاصطناعي والتخزين.  |     ضروري |
| `BUILT_IN_FORGE_API_KEY`      | مفتاح الخادم لخدمات Manus. لا تعرضه للمتصفح.          |     ضروري |
| `VITE_FRONTEND_FORGE_API_URL` | عنوان الخدمة التي قد تستخدمها الواجهة مباشرة.         | حسب النشر |
| `VITE_FRONTEND_FORGE_API_KEY` | مفتاح الواجهة عند الحاجة. لا تضع فيه مفتاحاً خادمياً. | حسب النشر |

### الهوية والتحليلات

| المتغير                     | الاستخدام                                               |          الحالة |
| --------------------------- | ------------------------------------------------------- | --------------: |
| `VITE_APP_TITLE`            | عنوان الموقع، مثل `المعلم الذكي`.                       |         اختياري |
| `VITE_APP_LOGO`             | رابط شعار التطبيق.                                      |         اختياري |
| `VITE_ANALYTICS_ENDPOINT`   | عنوان خدمة التحليلات.                                   |         اختياري |
| `VITE_ANALYTICS_WEBSITE_ID` | معرّف الموقع في خدمة التحليلات.                         |         اختياري |
| `NODE_ENV`                  | اضبطه على `development` محلياً و`production` في الخادم. |         موصى به |
| `PORT`                      | المنفذ الذي توفره الاستضافة. لا تثبّت رقماً داخل الكود. | توفره الاستضافة |

```env

VITE_APP_ID=معرف_تطبيق_Manus
OAUTH_SERVER_URL=https://api.manus.im
VITE_OAUTH_PORTAL_URL=https://oauth.manus.im
OWNER_OPEN_ID=معرف_مالك_المشروع
OWNER_NAME=اسم_مالك_المشروع

BUILT_IN_FORGE_API_URL=https://api.manus.im
BUILT_IN_FORGE_API_KEY=مفتاح_الخادم_السري
VITE_FRONTEND_FORGE_API_URL=https://api.manus.im
VITE_FRONTEND_FORGE_API_KEY=مفتاح_الواجهة_إن_لزم

VITE_APP_LOGO=
VITE_ANALYTICS_ENDPOINT=
```

القيم السابقة أمثلة لأسماء المتغيرات فقط، وليست قيماً صالحة للتشغيل. احصل على القيم الفعلية من إعدادات مشروع Manus أو مزود قاعدة البيانات والاستضافة.

> أي متغير يبدأ بـ `VITE_` قد يصل إلى كود الواجهة المبني للمتصفح. لا تضع فيه كلمة مرور قاعدة البيانات أو `JWT_SECRET` أو مفتاحاً خادمياً.

## إعداد قاعدة البيانات

اضبط `DATABASE_URL` أولاً، ثم نفّذ الهجرات. في بيئة التطوير يمكن استخدام الأمر الموجود في `package.json`:

```bash
pnpm db:push
```

ينفذ الأمر توليد ملفات الهجرة ثم تطبيقها عبر Drizzle Kit. في بيئة الإنتاج، راجع ملفات الهجرة قبل تطبيقها ولا تستخدم أوامر حذف أو إعادة إنشاء الجداول على قاعدة تحتوي بيانات مهمة. خذ نسخة احتياطية من قاعدة البيانات قبل أي تغيير بنيوي.

عند تعديل `drizzle/schema.ts`، اتبع هذا التسلسل:

```bash
pnpm drizzle-kit generate
# راجع ملف SQL الذي تم توليده
pnpm drizzle-kit migrate
```

تحقق بعد الهجرة من اتصال الخادم وظهور الجداول المطلوبة، خصوصاً جداول الدروس والمكتبة والاختبارات وبنك الأسئلة والإعدادات.

## التشغيل المحلي

شغّل خادم التطوير من جذر المشروع:

```bash
pnpm dev
```

افتح العنوان الذي يظهر في الطرفية، وغالباً يكون:

```text
http://localhost:3000
```

يعمل الخادم والواجهة عبر عملية تطوير واحدة، وتتم إعادة تحميل الواجهة تلقائياً عند تعديل ملفات React أو CSS. لا تنشئ طبقة REST إضافية للميزات الموجودة؛ استخدم إجراءات tRPC الموجودة في `server/routers.ts` والعميل الموجود في `client/src/lib/trpc.ts`.

## الاختبارات والبناء

نفّذ فحص TypeScript:

```bash
pnpm check
```

شغّل جميع اختبارات Vitest:

```bash
pnpm test
```

في النسخة الحالية تغطي الاختبارات الخادم والواجهة والتصدير والإعدادات والميزات التعليمية. يجب ألا تتجاهل اختباراً فاشلاً قبل النشر.

أنشئ نسخة الإنتاج:

```bash
pnpm build
```

ينتج الأمر ملفات الواجهة في `dist/public` وملف الخادم المبني في `dist/index.js`. شغّل نسخة الإنتاج محلياً:

```bash
NODE_ENV=production pnpm start
```

يجب تمرير `PORT` من بيئة التشغيل عند الحاجة، بدلاً من تثبيت منفذ داخل الكود.

يمكن تشغيل التنسيق عند الحاجة:

```bash
pnpm format
```

## تطبيق Android

يستخدم التطبيق غلاف Capacitor يحمل الموقع المنشور من العنوان الموجود في `capacitor.config.ts`. لذلك يحتاج التطبيق إلى اتصال بالإنترنت، وتستمر المصادقة والذكاء الاصطناعي وقاعدة البيانات والتخزين من خلال الخادم، ولا تُخزّن مفاتيح الخادم داخل APK.

### مزامنة مشروع Android

من جذر المشروع:

```bash
pnpm install --frozen-lockfile
pnpm android:sync
```

يقوم `android:sync` ببناء الويب ثم نسخ الملفات إلى مشروع Android وتنفيذ `cap sync android`.

### إنشاء APK تجريبي

```bash
cd android
./gradlew assembleDebug
```

سيظهر الملف هنا:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

لتثبيته على جهاز متصل ومفعّل فيه USB debugging:

```bash
./gradlew installDebug
```

أو افتح مجلد `android/` في Android Studio وشغّل التطبيق على جهاز حقيقي أو محاكي.

### نسخة النشر Google Play

لإنشاء حزمة AAB:

```bash
cd android
./gradlew bundleRelease
```

يتطلب إصدار النشر إعداد توقيع Android صحيحاً. خزّن ملف keystore وكلمات المرور خارج المستودع، ويفضل في أسرار GitHub Actions أو مدير أسرار الاستضافة. لا ترفع `*.jks` أو `*.keystore` إلى GitHub.

عند تغيير نطاق الموقع، عدّل `server.url` و`allowNavigation` في `capacitor.config.ts` ثم نفّذ:

```bash
pnpm android:sync
```

التفاصيل الإضافية موجودة في [ANDROID_BUILD.md](./ANDROID_BUILD.md).

## النشر على الاستضافة

### Manus WebDev

الطريقة الأسهل هي استخدام مشروع Manus WebDev، لأنه يوفر تشغيل Node.js وقاعدة البيانات والمصادقة وإدارة الأسرار والنشر عبر HTTPS. أضف القيم المطلوبة من لوحة الأسرار، ثم أنشئ checkpoint بعد نجاح الاختبارات. لا تضع `.env` داخل المشروع ولا تحاول تمرير مفاتيح الخادم إلى الواجهة.

العنوان المنشور الحالي للمشروع هو:

```text
https://smartplan-ppvujobi.manus.space
```

عند تغيير عنوان النشر، حدّث رابط `server.url` في إعداد Capacitor قبل بناء تطبيق Android جديد.

### خادم Node.js أو VPS أو منصة استضافة خارجية

تأكد أولاً من أن الاستضافة تدعم Node.js وعمليات تشغيل طويلة نسبياً واتصالات MySQL/TiDB ومتغيرات البيئة. نفّذ خطوات النشر النموذجية التالية:

```bash
git clone https://github.com/Almlek/teacher.git
cd teacher
corepack enable
corepack prepare pnpm@10.4.1 --activate
pnpm install --frozen-lockfile
pnpm db:push
pnpm check
pnpm test
pnpm build
NODE_ENV=production pnpm start
```

الإعدادات المقترحة في لوحة الاستضافة هي:

| الإعداد         | القيمة                                         |
| --------------- | ---------------------------------------------- |
| Build command   | `pnpm install --frozen-lockfile && pnpm build` |
| Start command   | `pnpm start`                                   |
| Node version    | Node.js 20 أو أحدث متوافق مع المشروع           |
| Package manager | pnpm 10                                        |
| Port            | قيمة `PORT` التي توفرها المنصة                 |
| Health URL      | `/` أو مسار فحص الصحة الذي توفره المنصة        |

طبّق الهجرات مرة واحدة في مرحلة نشر مضبوطة، وليس عند كل تشغيل لعملية الخادم إذا كانت المنصة تنشئ نسخاً متعددة. تأكد من استخدام HTTPS، وضبط نطاق OAuth، والسماح باتصالات قاعدة البيانات من عنوان الاستضافة، وتفعيل SSL لقاعدة البيانات حيثما كان متاحاً.

## النشر على Netlify

يمكن نشر واجهة الموقع من مستودع `teacher2` باستخدام إعداد `netlify.toml` المرفق. استخدم الإعدادات التالية إذا احتجت إلى إدخالها يدوياً:

| الحقل | القيمة |
| --- | --- |
| Base directory | فارغ |
| Build command | `pnpm build` |
| Publish directory | `dist/public` |
| Functions directory | فارغ |
| Branch | `main` |

يعيد ملف `netlify.toml` توجيه طلبات `/api/*` إلى خادم Manus المنشور، ويعيد توجيه بقية المسارات إلى `index.html` حتى تعمل مسارات Wouter المباشرة مثل `/lessons/new` و`/settings`. يجب ضبط قيم `VITE_APP_ID` و`VITE_OAUTH_PORTAL_URL` في Netlify قبل البناء إذا كانت مختلفة عن القيم الافتراضية، كما يجب التأكد من قبول نطاق Netlify في إعداد OAuth.

> نشر الواجهة على Netlify لا ينقل Express أو قاعدة البيانات أو خدمات الذكاء الاصطناعي؛ يبقى الخادم المشار إليه في `netlify.toml` مسؤولاً عن API والبيانات.

## النشر عبر GitHub Actions

يمكن بناء المشروع تلقائياً عند كل push إلى `main`. ضع القيم الحساسة في **Settings → Secrets and variables → Actions**، ولا تضعها في ملف workflow. الحد الأدنى لخطوات CI هو:

```yaml
- name: Install dependencies
  run: pnpm install --frozen-lockfile

- name: Type check
  run: pnpm check

- name: Test
  run: pnpm test

- name: Production build
  run: pnpm build
```

إذا أضفت بناء Android إلى CI، وفّر JDK وAndroid SDK، واستخدم keystore من أسرار مشفرة أو خدمة توقيع آمنة. لا تحفظ APK الموقّع أو بيانات التوقيع في المستودع الرئيسي.

## GitHub Actions: الاختبار والنشر المستمر

يحتوي المستودع على ملفين داخل `.github/workflows/`. يشغّل `ci.yml` عند كل `push` إلى `main`، وعند كل Pull Request يستهدف `main`، ويمكن تشغيله يدوياً. ينفّذ تثبيت الاعتماديات من ملف القفل، وفحص TypeScript، وجميع اختبارات Vitest، وبناء نسخة الإنتاج، ثم يحفظ `dist/` كـ artifact عند نجاح push إلى `main`.

يشغّل `deploy.yml` بعد اكتمال Workflow الفحص بنجاح على تحديث إلى `main`. وهو يستخدم **Deploy Hook** عاماً وآمناً من مزود الاستضافة، لذلك لا يرتبط بمزود محدد. عند عدم ضبط `DEPLOY_HOOK_URL` يتخطى Workflow خطوة النشر بدلاً من الفشل. يمكن تشغيله يدوياً من تبويب Actions، لكن التشغيل اليدوي ينبغي استخدامه فقط بعد التأكد من أن النسخة المراد نشرها اجتازت الفحوصات.

أضف الأسرار التالية من المسار **Settings → Secrets and variables → Actions** في مستودع GitHub:

| السر                                                         | الغرض                                                                                |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `TEST_DATABASE_URL`                                          | قاعدة اختبار منفصلة تستخدمها اختبارات الخادم. يوصى بها حتى لا تلمس CI قاعدة الإنتاج. |
| `TEST_JWT_SECRET`                                            | سر جلسات بيئة الاختبار.                                                              |
| `DATABASE_URL` و`JWT_SECRET`                                 | بدائل عند عدم وجود أسرار الاختبار، أو يمكن تخصيصها لبيئة النشر بحسب مزود الاستضافة.  |
| `VITE_APP_ID` و`OAUTH_SERVER_URL` و`VITE_OAUTH_PORTAL_URL`   | إعداد المصادقة عند حاجة اختبارات البناء أو التطبيق إلى قيم OAuth.                    |
| `OWNER_OPEN_ID` و`OWNER_NAME`                                | بيانات مالك المشروع المطلوبة في إعداد Manus.                                         |
| `BUILT_IN_FORGE_API_URL` و`BUILT_IN_FORGE_API_KEY`           | خدمات الذكاء الاصطناعي والتخزين أثناء التشغيل أو الاختبارات التي تستدعيها.           |
| `VITE_FRONTEND_FORGE_API_URL` و`VITE_FRONTEND_FORGE_API_KEY` | إعدادات خدمات الواجهة عند استخدامها في بيئة البناء.                                  |
| `DEPLOY_HOOK_URL`                                            | رابط Deploy Hook الذي يوفره مزود الاستضافة لتشغيل النشر بعد نجاح CI.                 |

لا تضع قيمة `DATABASE_URL` الإنتاجية في فرع أو ملف عام إذا كان من الممكن استخدام قاعدة اختبار منفصلة. كذلك لا تحفظ مفاتيح التوقيع أو keystore داخل GitHub؛ استخدم GitHub Secrets أو خدمة توقيع مخصصة.

## هيكل المشروع

```text
.
├── client/                  # واجهة React وCSS والصفحات والمكونات
├── server/                  # Express وtRPC والخدمات وقاعدة البيانات والتخزين
├── server/_core/            # بنية Manus الأساسية؛ عدّلها فقط عند الحاجة
├── drizzle/                 # schema وملفات الهجرات
├── shared/                  # الأنواع والثوابت المشتركة
├── android/                 # مشروع Android الناتج عن Capacitor
├── patches/                 # تصحيحات الاعتماديات
├── capacitor.config.ts      # إعداد هوية Android ورابط الموقع
├── ANDROID_BUILD.md         # تعليمات Android المختصرة
├── package.json             # الأوامر والاعتماديات
├── pnpm-lock.yaml           # قفل إصدارات الاعتماديات
├── vite.config.ts           # إعداد Vite
├── tsconfig.json            # إعداد TypeScript
├── vitest.config.ts         # إعداد الاختبارات
└── .gitignore               # استبعاد الأسرار والاعتماديات وملفات البناء
```

الملفات `node_modules/` و`dist/` و`.env` و`android/local.properties` وملفات `build/` المحلية لا ينبغي أن تكون جزءاً من commit. راجع `.gitignore` قبل رفع أي تغيير.

## الأمان والنسخ الاحتياطي

يجب أن تبقى `DATABASE_URL` و`JWT_SECRET` و`BUILT_IN_FORGE_API_KEY` وبيانات OAuth ومفاتيح التخزين على الخادم فقط. إذا تسرّب أي مفتاح، ألغِه أو دوّره فوراً من مزود الخدمة، ثم أعد نشر التطبيق.

تستخدم الملفات المرفوعة تخزيناً سحابياً، بينما تحفظ قاعدة البيانات المراجع والبيانات الوصفية. لا تخزّن محتوى الملفات الكبيرة داخل أعمدة قاعدة البيانات. اجعل صلاحيات الرفع مقيدة بالمستخدم المصادق عليه، واستخدم HTTPS في الإنتاج.

قبل أي هجرة أو عملية حذف، أنشئ نسخة احتياطية لقاعدة البيانات. ميزة النسخ الاحتياطي داخل المنصة تصدر بيانات التطبيق بصيغة JSON، لكنها لا تغني عن نسخة قاعدة بيانات كاملة ونسخة منفصلة من الملفات الموجودة في التخزين السحابي.

## استكشاف الأخطاء

| المشكلة                               | الإجراء المقترح                                                                                    |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| فشل `pnpm install --frozen-lockfile`  | تحقق من إصدار pnpm، ومن وجود `pnpm-lock.yaml` وعدم تعديل `package.json` دون إعادة توليد القفل.     |
| فشل الاتصال بقاعدة البيانات           | راجع `DATABASE_URL` وSSL والجدار الناري ووجود قاعدة البيانات، ثم نفّذ الهجرات.                     |
| فشل تسجيل الدخول                      | راجع `VITE_APP_ID` و`OAUTH_SERVER_URL` و`VITE_OAUTH_PORTAL_URL` ونطاق callback في إعداد OAuth.     |
| فشل الذكاء الاصطناعي أو رفع الملفات   | راجع `BUILT_IN_FORGE_API_URL` و`BUILT_IN_FORGE_API_KEY` وصلاحيات خدمة التخزين.                     |
| صفحة بيضاء بعد البناء                 | افحص سجلات المتصفح والخادم، وتأكد من تشغيل `pnpm build` من جذر المشروع ومن ضبط `VITE_` قبل البناء. |
| فشل Android بسبب SDK                  | تحقق من JDK 21 و`ANDROID_HOME` و`ANDROID_SDK_ROOT` والمنصة المطلوبة، ثم نفّذ `pnpm android:sync`.  |
| فشل `bundleRelease`                   | تأكد من إعداد keystore وبيانات التوقيع وعدم وضعها في Git، ثم راجع سجل Gradle.                      |
| عمل الموقع محلياً وفشله على الاستضافة | راجع `NODE_ENV` و`PORT` ومتغيرات البيئة وسجلات التشغيل وقابلية الوصول إلى قاعدة البيانات.          |

لفحص الحالة بعد النشر نفّذ:

```bash
curl -I https://your-domain.example
```

ثم اختبر يدوياً تسجيل الدخول، إنشاء درس، توليد اختبار، رفع صورة أو PDF، التصدير، وبناء التطبيق على هاتف Android حقيقي.
